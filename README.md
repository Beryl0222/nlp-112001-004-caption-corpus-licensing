# 镜头语言语料的文本派生与可撤销供数

场记与语料使用文件采用 UTF-8 编码，人物、单位和记录均为合成内容。

| 资料 | 字段 |
| --- | --- |
| `资料/镜头.json` | `id`、`series`、`revision`、`language`、`text` |
| `资料/说明提案.json` | `id`、`language`、`text`、`reportedBasis` |
| `资料/许可.json` | `id`、`source`、`issuedOn`、`licensor`、`text` |
| `订购.json` | `id`、`region`、`use`、`language`、`requestedOn` |

每份资料是 JSON 数组。记录中的字段值按来源原样保留为字符串，逗号和顿号可以属于字段内容。资料中可能有转述、不同的拼写以及较晚录入的更正。数字及日期在这些文件中沿用各资料自身的含义；原文位置以记录编号及文本范围定位。

Node.js 22 环境下运行以下命令可安装锁定的项目环境、检查素材格式并读取各类资料的数量。

```sh
npm ci --offline --ignore-scripts --no-audit --no-fund
npm test
npm run materials
```

`readMaterials` 只读取资料，不解析其中的正文含义。

## 工具能回答什么

在申请方给定的 **地区、用途、语言、评估日期（默认取订购 `requestedOn`）** 下，对每条描述稿给出一个可审核的决定：

| 决定码 | 含义 |
| --- | --- |
| `deliverable` | 事实有据、许可覆盖、无限制冲突，可按现状交付 |
| `deliverableWithAlternative` | 原依据失效，但另一素材独立支持同一事实且许可覆盖，可换源交付 |
| `needsCorrection` | 事实无据/被修订推翻/逐字限制冲突/授权撤回或缺失，必须更正 |
| `review` | 存在相关授权但范围不清楚，交人确认，绝不自动放行 |

### 事实派生规则（`src/facts.js`、`src/rules.js`）

- 描述可能是逐字转录、错字订正、翻译或概括，统一以**概念、动作、先后关系**的保留情况衡量，不做黑箱相似度判断。
- 每条主张带码点 `span`，可回溯到描述稿原句；支持结论回附镜头小句的 `span`，满足“每项文本事实能追到具体时间片段”。
- **画面推断不能写成镜头直接呈现的事实**：含倒影/推测/无法确认等提示的小句不支持直接主张。
- 同一 `series` 的较晚 `revision` 若含订正，只推翻其点名的动作，不株连其他动作（如 f4 只推翻 f1 的“挂灯”，不影响 f2）。
- 否定按局部作用域生效：“没有拍到开灯”不否定同句“灯一直亮着”。
- 语义等价与蕴含是显式声明的词表规则（`src/rules.js`），例如“进入/到达”蕴含“来客、室内”，翻译两端据此判断是否同一事实。
- 事实指纹使用概念/动作的多重集：**仅标点或分段变化不产生新交付；多出一个事实要素必然是不同语料**，不同素材各自有据的相似文本不会被合并。

### 许可与覆盖规则（`src/licenses.js`、`src/coverage.js`）

- 自然语言条款解析为结构化授权/撤回，附带原句与 `span`；无法确定的措辞（如“可继续讨论”“部分地区”）进入 `unresolved`/`review`，不臆测为授权。
- 许可未写语言时只覆盖素材原语言；跨语言（翻译、双语对照）必须有明确翻译授权或目标语言授权。
- 撤回只在其签发日期之后生效；期限按 ISO 日期比较，到期自动失效。
- “不能逐字保留招牌”等限制会与描述稿中的逐字引号比对，命中即要求更正。
- **替代来源**必须独立支持同一事实、且其许可覆盖当前用途；文案相似不构成替代。替代来源许可不清时只列入待确认。

### 双语对照（`src/assessment.js`）

订购记录可带 `"parallel": true`（或 CLI 加 `--parallel`）。此时会配对表达同一事实的中英文稿：两端各自许可都覆盖时才允许标为中英对照；任一端不覆盖对应语言时，单语材料仍可按自身决定处理，但**不得标成双语对照**。

### 交付台账与更正（`src/deliveries.js`）

台账是只追加的 JSON 文件，交付（`delivery`）、撤回（`recall`）、更正（`correction`）全部作为事件留存，旧交付及其当时采用的许可快照永不覆盖。许可变更后可按原交付标识发起更正，向接收方提供仍有效的版本，并通过 `audit` 查看完整更正链。

## 命令行用法

```sh
# 评估某个订购单（--date 可指定评估日期，--parallel 要求中英对照）
node src/cli.js assess o1
node src/cli.js assess o2 --date 2026-09-11 --parallel

# 单独评估一条描述稿在指定地区/用途/语言下的状态
node src/cli.js proposal d3 国内 广告 zh --date 2026-09-12

# 登记交付（不可交付会被拒绝；标点/分段变体自动去重）
node src/cli.js deliver o3 d3 --ledger 交付台账.json --date 2026-09-12

# 按原交付标识撤回并登记更正版本
node src/cli.js correct dlv-0001 --reason "原依据许可被撤回" \
  --replacement d3 --ledger 交付台账.json --date 2026-09-20

# 查看仍有效的交付，或某条交付的完整更正链
node src/cli.js audit --ledger 交付台账.json
node src/cli.js audit dlv-0001 --ledger 交付台账.json

# 判断两条描述稿是否表达同一事实
node src/cli.js same-fact d2 d3
```

输出均为 UTF-8 JSON：决定码为英文、解释为中文，便于程序消费与人工审核。

## 当前合成数据的结论速览（评估日 2026-09-11 之后）

- `d1`：挂灯主张被较晚修订 f4 推翻、先后关系与招牌位置无镜头支持、且逐字保留被 l1 禁止的招牌文字 → `needsCorrection`，无替代素材。
- `d2`（英文）：事实可由 f3 支持，但 f3 无英文翻译授权；替代来源 f2 的英文教育许可已被 l4 撤回 → `needsCorrection`，不得自动替换。
- `d3`（中文）：f2、f3 独立支持同一事实；f2 失效后可改用 f3（l3 覆盖国内教育与广告，至 2027-03-31）→ `deliverableWithAlternative`。
- `d2` 与 `d3` 表达同一事实，但英文端无授权，故不能标成中英对照语料。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `materials.js` | 原样读取并校验四类资料 |
| `src/source.js` | 来源编号解析、码点 span、小句切分、文本规范化 |
| `src/rules.js` | 显式声明的语义等价与蕴含规则 |
| `src/facts.js` | 事实抽取、镜头支持判断、修订推翻、替代来源、指纹 |
| `src/licenses.js` | 许可条款结构化解析 |
| `src/coverage.js` | 地区/用途/语言/期限/撤回的覆盖判断 |
| `src/assessment.js` | 订购评估、替代换源、双语对照、逐字限制 |
| `src/deliveries.js` | 只追加交付台账、去重、撤回与更正链 |
| `src/cli.js` | 命令行入口 |
